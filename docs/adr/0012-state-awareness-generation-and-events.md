# State awareness: generation counter, change-event log, and external-change detection

Clients need to know what happened to the editor state without re-reading the whole document. Every StateSnapshot carries a monotonic `generation` — bumped on every state-changing operation (edits, undo/redo, mode changes, Open/Save), never on pure reads — so a client can tell at a glance that something changed since its last snapshot. The daemon also keeps a bounded ring of ChangeEvents (128): one per state-changing operation, tagged with its source (Interactive for the TUI, Headless for session exec/edit, External for out-of-band file changes) and its kind (Insert, Delete, ReplaceRange, Undo, Redo, Open, Save, SetMode, ExternalChange, …). The ring rides in every snapshot so one-shot clients stay self-contained.

Source is determined by a client-kind handshake: the first message on a connection is `Hello { kind }` (mirroring LSP's initialize); the TUI declares `interactive`, everything else is `headless`. Message type alone cannot distinguish user from agent — an agent driving the editor via session exec sends the same Command messages as the TUI — so the declaration is required.

Interaction-only operations (cursor moves, scrolling) are not logged: their current result is always visible in the snapshot's selection and viewport, and logging them would flood the ring and evict the edit events that matter. The log covers document-affecting operations and lifecycle events only.

Separately, the daemon detects out-of-band modification of the focused document: it records (path, mtime, size) at Open and after each successful Save, and a background task stats the file every ~1–2 seconds. A mismatch produces an ExternalChange event, bumps the generation, and sets a `disk_changed` flag in the snapshot. The daemon never auto-reloads — a document must never be clobbered from disk (the same principle as the already-open-path fix, #7) — detection and reporting only. mtime+size is an acknowledged heuristic: tools that preserve mtime, or filesystems with coarse mtime granularity, can slip through. Edits target the focused document (an agent Opens before editing), so focused-document monitoring covers the whole surface.

Save-time conflict handling (refusing or warning when the disk changed since the last baseline) is deferred to a follow-up. A `GetEvents { since }` query is a possible extension if clients need events older than the ring. This spec is orthogonal to the deferred two-stack undo design.
