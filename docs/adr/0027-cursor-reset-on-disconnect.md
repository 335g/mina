# 最後の TUI 切断でカーソルを先頭へ戻す（reset_cursor_on_disconnect）

TUI クライアントの切断時に、デーモンが保持する全 View のカーソル（Selection）とビューポートを初期位置（文書先頭・1行目）へ戻す。デフォルト有効で、`reset_cursor_on_disconnect = false` で無効化できる。

## 動機

カーソルはデーモンが保持するため、TUI を閉じても開き直しても前回の位置に残る（仕様として正しかった）。しかし TUI が切れた後に残るカーソル位置は「表示する人がいない UI 状態」であり、再開時に前回の場所の途中から開かれて混乱する。保持する価値があるのは文書・undo 履歴・LSP セッション（WorkspaceRoot 単位で温かいまま保持）であり、カーソルではない。デーモンは UI 状態を持つべきでない、という設計思想に沿う。好みが分かれる挙動なので、設定キーで切替可能にする（デフォルトはリセット）。

## 決定

- **トリガ**: 最後の Interactive クライアントの切断時。他に Interactive クライアントが接続中ならリセットしない（複数 TUI 構成で他クライアントのカーソルを踏まない）。Headless の切断は対象外（エージェントはカーソルを動かさない）。
- **範囲**: 全 View（開いている全文書）の Selection → `point(0)`、viewport → `first_line = 0`。フォーカス文書のみでなく全 View — どれも「見る人がいない UI 状態」だから。
- **フラグの伝搬**: 設定はクライアントローカルのまま、TUI が起動時に `config.toml` を読み、接続時の `Hello` メッセージに `reset_cursor_on_disconnect` を載せる（`Hello` にフィールド追加）。「Daemon は config を読まない」という Config のドメイン不変条件を維持する。リセットの要不要は**切断した**クライアントの宣言値で決まる。
- **状態変化として扱う**: リセットは generation バンプ + ChangeEvent を出す（`EventKind::SelectionReset`、source は `External` — クライアント操作でなく daemon 起因）。`record_event` 経由なので WaitFor 待ちエージェントが起床し、イベントリングに記録される。
- **文書・undo 履歴・LSP は不変**: 本変更は Selection と viewport のみに作用する。`Close` は従来どおり文書と undo 履歴を破棄する破壊的操作のまま（「このファイルを閉じる」という明示的操作）。

## 互換性

- 旧クライアントの Hello（新フィールドなし）は serde の `#[serde(default = true)]` で「リセットする」として扱う — 新デフォルトと一致する。
- 旧デーモンは Hello の未知フィールドを無視する（`deny_unknown_fields` なし）ため、新クライアントはそのまま接続できる。

## 代替案の却下

- **TUI 起動時にローカルで先頭へ**: デーモンの状態は古いまま残り、TUI 未接続の間エージェントの GetState に古いカーソルが見える。カーソルを「接続スコープの状態」にする思想と不整合 → 却下。
- **デーモンが config.toml を読む**: 「Daemon は config を読まない」という Config のドメイン定義に反する → 却下。
- **デフォルト無効（オプトイン）**: 「再開時に途中から開かれて混乱する」という主訴がデフォルトで再発する → 却下。無効化したいユーザーはキーで opt-out する。
