# Command/DocumentEdit の分割: 選択連動型と位置指定型の操作

ワイヤプロトコルは 2 つの操作面を区別する。`Command` は選択連動型の面である: 共有 Selection を読み、変更することがあり、対話型 TUI (Keymap 経由) と TUI を駆動するエージェント (`session exec`) が送るものである。`DocumentEdit` は位置指定型の面である: 明示的な文字レンジへの insert/delete/replace であり、Selection を読まず変更もしない。ヘッドレスクライアント (`session edit`) が送るもので、TUI のカーソルに左右されずにドキュメントを編集したい場合に使う。代替案 — 位置指定バリアントを持つ単一の共有コマンド型と「TUI は選択ベースのものだけを使う」という規約 — は却下された: 同じクライアントが選択ベースと位置ベースの 2 つの有効な編集方法を表現できてしまい、呼びやすい方に退化する曖昧さが残る。型を分割することで境界は構造的になる: TUI は DocumentEdit を表現できず、DocumentEdit はカーソルを乱さない。両面はトランスポート (ローカルソケット上の NDJSON)、スナップショット応答、Transaction 機構 (undo グループ、dirty、LSP 同期) を共有する。
