# WorkspaceRoot スコープの LSP セッション

LSP セッションは WorkspaceRoot ごとにスコープされる — 開かれたファイルを含む最小の解析単位 (最寄りの `Cargo.toml`、なければ最寄りの `.git`、なければファイルの親ディレクトリ) — グローバルな単一セッションではなく。デーモンは WorkspaceRoot からセッションへのマップを保持するので、異なるプロジェクトのファイル (例: `crates/` 配下の別々の crate) はそれぞれそのプロジェクトをルートとする独自の rust-analyzer を得る。またデーモンが生きている間、セッションが刈り取られることはない (ADR-0005 のウォームな LSP 高速アタッチ)。単一セッションの代替案は却下された: 最初のファイルのディレクトリで初期化された共有サーバーは、後のプロジェクトのファイルを誤解析し、その `rootUri` はワークスペースルートを指していなかった。スナップショット内の診断はフォーカス中のドキュメントのもののみである。
