# Space k の定義 peek ポップアップ: 見た目と配色

`Space k` (`Command::PeekDefinition`) はカーソル位置のシンボル定義をジャンプせず確認する。応答は `StateSnapshot.peek` に載り、クライアントローカルの一時表示として次のキーで消える (ADR-0023 以前からある deleted ポップアップと同じ「任意キーで閉じる」流儀)。

ポップアップの構成は「1行目に定義元リンク (パス:行番号) → 直下に空行 → 定義スニペット数行 → `(any key closes)` → 最下の空行」とし、ヘッダ直下と最下端に縦の余白を持たせる。**box 罫線 (┌─┐│└┘) で囲み、内容は 1 セル内側に配置する。**

配色はカラースキームで管理する: 中身 (背景・フォント色) は `UiRole::Popup`、枠線の前景色は `UiRole::PopupBorder`。境界の背景は Popup に揃える (popup_border_sgr が Popup の背景を流用する) ため、ユーザースキームが背景色を変えても追従する。罫線を加えたのは、ポップアップ背景 (多くのスキームで端末既定の黒に近い暗色) が編集画面と同化して見切れるため。

Doc テキスト (hover) と内部スクロールは**意図的に実装しない** — シンプルさを優先し、実際に欲しくなったら追加する (ponytail: YAGNI)。

重要な既知の落とし穴: **既定 (`DEFAULT_UI`) の Popup は `Style::reverse()` (白反転) ではなく明示的な bg+fg にする。** ユーザースキームとのマージ `layered()` は属性を OR で継承するため、`reverse` を既定にすると、スキームが `popup = { fg, bg }` と明示しても `reverse` が残り、暗色 bg が白く浮いて見える — 全カスタムスキームに波及する見た目の不具合の根因だった。明示 bg+fg にすることで、ユーザースキームの指定がそのまま効く。
