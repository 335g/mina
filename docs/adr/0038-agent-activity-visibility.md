# エージェント活動の可視化（リモートカーソルは不採用）

エージェントの「カーソル可視化」は採用しない。エージェント（minas）はワンショット接続でカーソルを持たないため、見せる対象が存在せず、長命エージェントセッションの新設（セッションモデル全体の拡張）を要求するため。代わりに**活動可視化**（エージェントが「何をしたか」）をプロトコル拡張として導入する:

- **Hello に `name: String`**（既定 `unknown`）。**自己申告ラベル**（HTTP User-Agent 的・未認証 — セキュリティ境界ではなく「誰の操作か」を見るための札）。minas は `MINAE_CLIENT_NAME` を読み、`--name` で上書き可。複数エージェントは各プロセスが自分の名前を設定するだけで区別される（デーモンは受け取った文字列をスタンプするだけ）。TUI は既定 `tui`
- **StateSnapshot に `activity: Vec<ActivityRecord>`**（bounded リング・既定 100 件。`{ actor, kind, ok, detail }`）。**generation を進めて push に乗せる**（events と同じ配線）
- **記録対象**: Headless 由来の「状態を変えようとした操作」（Open / 編集 / Save / Rename / Close …）の**成功と失敗**。読み取り系は記録しない。失敗 = checksum / expected_text 不一致拒否・Open 失敗など。ChangeEvent（状態変更の記録）は現状維持で並存 — activity は「操作の試行と結果」の履歴
- **表示**: ステータス右側報知エリアに「今の活動」+ 履歴オーバーレイ（全幅・高さ約 30%・下側固定・診断 view と同型）+ フィルタ（全 / 成功のみ / 失敗のみ — エラー率評価用）

Status: accepted

## Considered Options

- リモートカーソル（エージェント・TUI ピア間とも）: 上記の理由で棄却。TUI ピア間も「エージェントと同じ扱い」として棄却（`peers` フィールドは追加しない）
- クライアントローカル蓄積: TUI 接続前の履歴・再接続後の履歴が失われ、失敗率評価の信頼性が落ちる → 棄却
- 専用 pull コマンド（GetActivity）: ステータス報知と履歴でデータ源が分かれる → 棄却
