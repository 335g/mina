# 外部変更への自動追従: ADR-0012 の「自動リロードしない」条項を覆す

ADR-0012 は外部変更を検知・報告のみとし「デーモンは自動リロードを決して行わない」と定めた。しかし TUI を閉じた間に別ツールがファイルを編集して再オープンすると、デーモンが保持する編集前の状態が表示され続ける。検知があっても追従しないため、デーモンのメモリ状態がディスクから乖離したままになり、エージェントも変更を気付けない。そこでデーモンは外部変更を検知した瞬間に自動リロードする。2 秒ポーリング (mtime+size) は維持し、対象をフォーカス文書から全オープン文書 (文書ごとのベースライン) に拡張する。

## 動作契約

- **リロードは Dirty でも常時行う**。Transaction として記録され undo 可能 — 外部変更前の状態 (未保存の編集込み) に戻れる。
- リロードは Insert UndoGroup を閉じ、モードを Normal に戻す (ADR-0007 の外部書き込みと同原則)。
- リロード後、テキストはディスクと一致するため Dirty はクリアされる。
- `ExternalChange` イベントは維持 (generation 増加 → エージェントの `WaitFor` が気付く)。**`StateSnapshot.disk_changed` フラグは削除** — 乖離が恒常状態でなくなるため。
- リロードは文書の同一性を変えない (ID・Path・LSP セッション対応は維持)。
- Open 文書のリロード時は LSP に didChange 全文同期 + pull 診断を送る (通常編集と同経路)。
- **外部削除**: フォーカス文書の削除を `StateSnapshot.deleted` で保留表示。TUI は中央モーダル + 任意キー → 新コマンド `Command::Close` で文書を閉じ、空画面 (ファイル未オープン状態) に戻す。Dirty の場合は損失の警告を表示する。Save は削除状態を解消する。
- **監視対象は全オープン文書のみ**。未オープンファイルの監視はしない。

## 検討した代替案

- **Dirty 時はリロード拒否** (データ損失保護): undo 可能な Transaction として実装することで損失が回復可能になり、常時リロードの単純さを採った。
- **未オープンファイルの監視 + `didChangeWatchedFiles` 配線**: サーバ非依存化のためのコストであり、現行サーバ (rust-analyzer) は自前のファイル監視を持つため見送った。
- **新イベント種別 (`ExternalReload`)**: リロードも削除も「外部変更が起きた」という事実の記録であり、結果はスナップショットのテキストと `deleted` フィールドが見せるため、種別の追加はしなかった。

## 帰結

- 保存済みの編集が外部変更で置き換えられるリスクは undo でしか回復できない (undo 履歴は現在 unbounded)。
- 非フォーカスの Open 文書が外部削除されても TUI には表示されない (フォーカス移動コマンドが無いため)。Open 時の re-stat で検知される。
