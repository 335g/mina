# 接続別フォーカス分離（per-client focus separation）

デーモンは**接続ごとに 1 つの View（doc / selection / first_line）**を持ち、フォーカス文書・カーソル・ビューポートを接続別に独立させる。文書集合・undo 履歴・LSP セッションはデーモン共有のまま（**ロード = 共有、フォーカス = 接続別**の切り離し）。これは「人が開いた操作がエージェントに引きずられる／エージェントの Open に TUI が引きずられる」結合を解消する再構想の中核である。

- **Open コマンドの意味論**: 「ロード（共有・既ロードなら再利用）+ 自分の View をその文書へ」（Interactive）/ 「ロード + idle view の文書を更新」（ヘッドレス）。「ロードのみ」「フォーカスのみ」の別コマンドは YAGNI として追加しない
- **ヘッドレス**: View を持たない（操作対象パス明示・応答は target のスナップショット）。共有 **idle view** を 1 つ維持（パス無し GetState の観測点。「最後に開かれた文書」）。`reset_cursor_on_disconnect`（ADR-0027）は最後の Interactive 切断時にこの idle view のカーソルへ適用（既定 true）
- **スナップショット/push**: StateSnapshot は接続別に合成され、push（ADR-0013）は購読者ごとの View を反映した snapshot を配る（ADR-0006「全量」は維持・接続別合成へ）
- **LSP**: 複数セッションは WorkspaceRoot 単位で既存（ADR-0010）。セッション内は**共有解析フォーカス 1 文書**（最後に解析要求された文書）。診断・inlay はその文書を見る View のスナップショットにのみ載る。単一フォーカス文書は LSP プロトコルの制約ではなく実装単純化（didOpen は複数文書可）— 将来の複数開き・並列 root 閲覧（コミット比較含む）に拡張可能なまま維持する

Status: accepted（ADR-0005/0006/0013/0027 の意味論を一部改変）

## Considered Options

- 接続ごとに完全独立（文書集合まで分離）: 同一パスに複数の正統 Document が生まれ、検証付き編集（checksum）・外部変更自動リロード・dirty 追跡が壊れる → 棄却
- TUI 純ビューワー化: ツリーの存在意義（自分のフォーカスで開く）と矛盾 → 棄却
- リモートカーソル可視化（当初の分離ビジョン）: エージェントはワンショット接続でカーソルを持たず、長命セッション新設を要する → 「活動可視化」（ADR-0038）に置き換え
