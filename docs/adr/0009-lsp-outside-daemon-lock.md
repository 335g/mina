# LSP はデーモンロックの外で動作し、次の Open で再起動する

LspSession は Daemon 内部で独自のミューテックス (`Arc<Mutex<LspSession>>`) の背後に存在する。spawn、`initialize`、`didOpen`、`didChange` はデーモンロックの外で await され、それぞれタイムアウトで制限される (書き込み 2s、リクエスト 10s)。診断ドレインは `try_lock` を使うので、ビジーなサーバーがコマンド処理をブロックすることはなく、セッションロックの取得自体も制限される (3s) ので、ロックを握ったままのサーバーが Open や編集の応答を止めることはない。根拠: v1 の主要用途は人間の TUI がアタッチする間のエージェント駆動編集であり、遅いまたはハングした言語サーバーは全クライアントではなく編集パイプラインを止めるべきである。以前はデーモンロックが LSP I/O の間保持されていたため、1 つのハングした rust-analyzer がすべてのセッションを凍結した (書き込みタイムアウトがなかったため恒久的に)。サーバーが死んだ場合 — リーダータスクが EOF に達したときに通知チャネルが閉じることで検出 — 編集の同期は (無駄なタイムアウト待ちなしで) 静かに止まり、古い診断はスナップショットから消去され、セッションは次の .rs の Open で再起動する (`initialize` + `didOpen` を最初からやり直す)。再起動ループはあり得ない — 再起動は Open でのみ発生し、壊れたサーバーの `initialize` 失敗はスナップショットのステータスに現れるからである。
