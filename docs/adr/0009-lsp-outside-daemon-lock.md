# LSP runs outside the daemon lock and respawns on the next Open

The LspSession lives behind its own mutex (`Arc<Mutex<LspSession>>`) inside the Daemon. Spawning, `initialize`, `didOpen`, and `didChange` are awaited outside the daemon lock, each bounded by a timeout (2s writes, 10s requests); diagnostic drains use `try_lock` so a busy server never blocks command processing. Rationale: v1's primary use is agent-driven editing while a human TUI attaches — a slow or hung language server must stall the editing pipeline, not every client. Previously the daemon lock was held across LSP I/O, so one hung rust-analyzer froze all sessions (and, with no write timeout, permanently). If the server dies — detected via the notification channel closing when the reader task hits EOF — edits stop syncing silently (no wasted timeout waits) and the session respawns on the next .rs Open (re-`initialize` + `didOpen` from scratch). No respawn loop is possible because respawn only happens on Open, and a broken server surfaces its `initialize` failure in the snapshot status.
