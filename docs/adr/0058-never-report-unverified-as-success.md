# 確信できない答えを成功として返さない（reload 窓・unlinked・WaitFor）

ドッグフーディング（2026-09-13、driver 報告 #3 / #4 / #5 / #10）で、**同じ失敗クラス**が
4 箇所から出た: ツールは「見ていない」ときにも「見た結果こうだった」と同じ形で答えていた。

| # | 症状 | 実測 |
|---|---|---|
| #3 | 新規作成したファイルの `check` が `hints (1)` / **exit 0**。3 秒後に同じコマンドが `errors (1)` / exit 2 | `tests/cold.rs` を作って直後に `check` |
| #4 | 再ロード中に `check --crate-root` がパスごとに `failed`（"no usable diagnostics response"）+ exit 2。原因は「まだ索引中」なのに**プロトコルエラーとして報告** | 新ファイル追加で 2/4 回 |
| #5 | `peek` が「定義なし」と「まだ解決できない」を区別せず、**line=0 / text="" を exit 0** で返す | 編集直後の 4 列のうち 2 列が空、1 秒後に全部解決 |
| #10 | `wait <未来の世代>` が 0.5 秒で現状を返し **exit 0**（待っていない） | `wait 999999` → 0.53s / 現状 |

どれも「無言の誤り」の変種で、エージェントの次の行動（commit する / 定義があると信じる /
相手の編集が届いたと信じる）が**根拠なく**進む。ADR-0045（空はクリーンの根拠にしない）の
精神を、check 以外の経路と「成功応答の形」に広げる。

Status: accepted

## Decision

1. **索引完走ゲートをラウンドごとに再武装する**（`mina-lsp::Progress`）。
   `Progress.ready` は「1 セッション 1 回」だった（ADR-0051）。ワークスペースは
   1 回ロードして終わりではなく、**ファイル集合が変わると（`mod` 宣言の追加・新規
   ファイル）rust-analyzer は cargo を再ロードする** — 2 回目以降のラウンドを
   「準備完了」と誤認し、その窓の応答を確定として返していた（#4 の `Protocol`
   誤分類、#5 の部分的な空 peek はどちらもこれ）。
   新しい分析ラウンド（`outstanding` が空のときの `begin`）で `ready = false` に戻す。
   - **flycheck は除外する**（`rust-analyzer/flycheck/N`）。分析能力と無関係で、
     待つと save のたびに cargo check 1 回分の遅延を要求ごとに払うことになる。
   - 相次ぐ phase の begin では `outstanding` が空でないため、再武装はラウンドの
     先頭でだけ発火する。
2. **`unlinked-file`（どのクレートにも属していない）を未検証として扱う**。
   `check` は `unlinked-unverified` を返し、**exit 2** に倒す（`hints (n)` + exit 0
   は「警告だけのクリーン」に見えるため）。プロジェクト外（rust2 #21）も同じ
   verdict で同じく exit 2 に揃える — 「見ていない」は exit 0 にしない。
3. **`WaitFor` は target 世代に達するまで返らない**。ADR-0014/0012 の締切
   （内容変化なしの fallback / settle 窓 / hard cap）は「**世代を超えた後**」の
   話で、以前は未到達でも fallback で打ち切って現状を返していた（#10）。
   未到達の間は fallback 窓ごとに再評価して待ち続ける（上限は呼び出し側の
   `WAIT_TIMEOUT` = 90s、CLI が exit 2 で現状を返す）。
4. **skill を更新**: `check` の verdict / exit の意味（0 と 2 の分岐点）と、
   `unlinked-unverified` が「新規作成直後に見えるもの」であることを明記。
5. **空の `check` も「見たのか」を確かめる**（round 3 の残り）: 空が返ったとき、
   索引/再ロードのラウンドが進行中なら `Progress::wait_ready` で静まるまで待って
   引き直し、静まらなければ `PullFail::NotReady`（再試行可能）を返す。
   driver の再検証で 9 回中 1 回、**pull が空を返し、unlinked-file Hint がまだ
   現れていない窓**で `clean-unverified` + exit 0 が返った（`cargo` は E0308）。
   修正後の実測: 新規ファイルを作って即 `check` × 5 回 → すべて exit 2
   （`unlinked-unverified` / `errors (1)`）、`clean-unverified` + 0 は 0 件。
6. **`peek` は「まだ解決できない」空を確定しない**（round 3 の残り）: 定義が
   取れなかったとき、(a) 索引が not ready なら静まるまで待つ、(b) 索引が静かでも
   **位置が識別子**なら短く待って 1 回だけ引き直す。実測: ファイルを crates に
   繋いだ直後の最初のスイープは `let v = zeta(1);` の `z` だけ空（同じスイープの
   `e`/`t`/`a` は当たる）、修正後は 5 列すべてが当たる。空白・演算子・キーワードの
   「定義なし」（正常な答え）は待たない。
7. **エージェントが分岐できる失敗の形にする**（#12）: 基準 root 配下の編集拒否は
   `read-only-base:` で始まる安定 ASCII コード + 英語本文（他の agent 向け診断
   — `cannot open` / `NOT FOUND` / `file too large` — と同じ言語に揃える。
   prose を文字列マッチしないと分岐できない状態をやめる）。加えて
   `RegisterBaseRoot` 時点で、登録 root 配下に**開いている文書**があれば警告を
   返す（原因のコマンドで知らせる — 失敗は 1 コマンド後に遠くに出ていた）。
   拒否ではなく警告なのは、同じパスを別 commit で登録する compare-review の
   使い方が正当だから。

## Considered Options

- **reload を待たずに「未検証」を返すだけ**（#3 を honest refusal にする）:
  却下（単独では）— 偽グリーンは消えるが、`create → check → commit` のループが
  「exit 2 を見て待って再実行」になり、ツールが代わりに待てる待ちを
  エージェントに押し付ける。ADR-0051 のゲートがあるのに再ロードだけ素通し
  だったのが穴なので、まずゲートを直す。
- **`unlinked-file` を見て待ってから再 pull する**（プローブで解決を待つ）:
  却下（今は）— 待ち時間の根拠が「だいたい数秒」しか無く、ループ工学の
  反復（#5/#6/#8 で固定待ちを全部外した）と逆行する。正直に未検証を返し、
  待つかどうかは呼び出し側に残す。実測が待ち時間を要求したら別の反復で。
- **`Progress.ready` を捨てて毎回静止確認する**: 却下 — 1 要求ごとに
  300ms を払う（ADR-0051 が明示的に避けた設計）。
- **flycheck も含めて再武装する**: 却下 — save のたびに cargo check 1 回分を
  待つことになり、#5/#6/#8 で削った遅延を戻す。
- **`wait` の fallback を 500ms → 大きくする**: 却下 — 未来の世代を渡された
  ときに「待たずに現状を返す」という契約違反自体が問題で、窓の長さではない
  （500ms でも 5s でも、返れば偽成功）。
- **`wait` の説明を「settle を待つだけ」に直す**: 却下 — 2 ペイン同期の用途は
  実在し、CLI に 90s のタイムアウトが既にある。ブロックするのが正しい。
- **peek / hints の空応答に `error` を足す**（#5 の残り・`hints` の穴）:
  延期 — 原因（未解決 vs 定義なし）の区別には LSP の応答だけでは足りず、
  「解決できなかった」を別の値として定義する必要がある。backlog
  （`.pi/todos`）に置き、wire 変更をまとめる回で扱う。
  （decision 5/6 で「待てば当たる空」は減らしたが、「本当に定義なし」と
  「サーバが null を返した理由」の区別は依然として値に無い。）

## Consequences

- 再ロード窓の答えは「待ってから正しい答え」または「未検証」のどちらかになり、
  「間違った確定」にはならない。
- `check` は exit 2 の意味が広がる: **0 = 見て、エラーが無かった / 2 = それ以外**
  （エラーあり・見られなかった・対象外）。エージェントは 0 のみを前進の根拠にする。
- 未到達の `wait` は呼び出し側のタイムアウトまでブロックする（CLI は 90s で
  exit 2 + 現状を返す）。
- テスト: `Progress` のラウンド再武装、`is_unlinked_file` の 2 文言、
  `wait_for_generation_blocks_until_change` に「fallback 窓を過ぎても
  ブロックし続ける」assert を追加。全パッケージ 409 + minad 203 green。
