# Undo グループは Insert を抜けるときとクライアント切断時に閉じる

UndoGroup — 単一の undo で巻き戻される Transaction の集合 — は正確に 1 回の Insert セッションにまたがる: エディタが Insert モードに入ると開き、Insert を抜けると (Normal または Select に) 閉じる。また、Insert 中に所有 Client が切断した場合も閉じる (この場合エディタも Normal に戻る)。代替案 — Insert→Normal のときだけ閉じる — は、グループが Select 遷移の間ずっと開いたままになり、さらに悪いことにクライアントの増減を通じて開いたままになる: デーモンとその History は永続的 (ADR-0005) なので、閉じられていないグループは異なるセッションの編集を 1 つの undo 単位に統合し、undo の粒度を静かに破壊する (前回セッションの編集が 1 回の undo で消える)。

接続スコープのグループは当初 v1 で却下された — 事実上 1 クライアントのモデルではデーモン側の境界で十分に見えた。文書化された主要ワークフロー (人間の TUI が介入するエージェント駆動編集) がその前提を破った (HIGH-1): 人間の Insert セッションが開いている間にワンショットのエージェント接続が終了すると、グループが閉じられモードが Normal にリセットされ、エージェントの編集が人間の開いているグループに統合された。したがってグループは接続ごとに所有される: `SetMode(Insert)` でグループを開いた Client が所有者であり、切断して閉じられるのは所有者のみ。他の Client からの書き込みはまずグループを閉じる (最後の書き込みが勝つ — 競合する書き込みはインターリーブせず直列化されるため、単一の UndoGroup に異なる Client の編集が混在することはない)。所有権はデーモン側で追跡される (プロトコル変更なし): グループの開閉はデーモン駆動のままなので、グループスコープをワイヤ型で明示する必要はない。将来のマルチクライアントモデル (複数の対話型 View) では、グループスコープをプロトコルで明示することで再検討できる。
