# レビューコメントの daemon 保持と比較→AI 連携（#50）

比較レビューで付けたコメントを AI に投げるため、差分アンカー（側・パス・行・
行スナップショット＋コメント本文）を daemon 共有の箱に保持し、AI は
`minas review` で抽出する。ファイル出力を挟まず、後日の minae 内ターミナル
（#54）からも同じ抽出コマンドを再利用する。読取りコマンドの形状追加ではなく
管理対象の新規状態＋3 コマンド追加に留め、ADR-0039 の bump 方式（v14）に収めた。

Status: accepted

## Considered Options

- ファイル出力（比較＋コメント一覧.md）: 却下 — 永続化・パス管理・陳腐化の
  面倒が残り、grill で「あっちいったりこっちいったり」の煩雑さが指摘された。
  隣ペインのエージェントが見るにしても daemon 保持の方が世代対応できる。
- クリップボード（OSC52）: 却下 — tmux/ssh で割れ、大量差分で上限に当たり、
  永続なし。複数件一括に向かない。
- TUI の View に保持: 却下 — `minas` は別接続のため見えない（ADR-0037 の
  接続別合成と衝突）。daemon 共有が必須。

## Consequences

- 追加は同一アンカー（パス・側・行）で上書きし、空本文はそのアンカーの削除
  とする（per-anchor 削除の専用コマンドなし）。追加・更新・削除・全消しは
  世代を進め `EventKind::ReviewComment` に載る。
- 一覧応答は照合結果（`stale`＋`resolved_line`）を添えるが保存値は書き換えない
  — ずれた先の判断は AI が行う。スナップショットには件数のみ載せ、全文は
  List 応答だけに載せる（push 肥大化の回避）。
- 寿命は再ピン（基準点が変わったとき）・Unregister・明示 Clear でのみ全消しし、
  TUI 切断では保持する。同一ペアの再登録（表示切替・再接続）は保持する。
- headless ゲートの例外: `ListReviewComments` と `ClearReviewComments` は
  headless に許可する（抽出と TUI 死後の掃除用）。`AddReviewComment` は
  TUI 駆動のみ（#49 の基準登録と同型）。
- ADR-0037 との緊張: コメントは接続別 View ではなく daemon 共有の新規状態で
  あることを明記する（別接続の `minas` から見える必要があるため）。
