# `?` は後方検索をやめてキーバインドヘルプを開く

minae は Helix 準拠バインディングを標榜しており、`?` は従来
**後方検索プロンプト**を開いていた（`/` が前方検索）。ヘルプを
「`?` 1 キーで開く」を優先し、後方検索プロンプトは廃止する。

Status: accepted

## Decision

- `?`（Normal/Select）は **`Overlay::Help`（ヘルプオーバーレイ）** を開く。
  中央 50% サイズのクライアントローカル表示で、全モードのキーバインドを
  一覧表示する。Esc または再び `?` で閉じる。
- `/` は前方検索プロンプトのまま。**後方検索は `?` で開けなくなる**が、
  前方検索後に `N`（後方へ移動）で到達できるため機能面の損失は小さい
  と判断した。
- `Prompt::Search` は前方のみになったため `forward` フィールドを削除し、
  `Search(String)` に単純化した（プレフィックスは常に `/`）。

## Considered Options

- **F1 = ヘルプ（Helix と同じ）、`?` は後方検索のまま**: 損失ゼロだが、
  ユーザーが「`?` でヘルプを開く」ことを明示的に選択した。
- **`?` = ヘルプ、後方検索は `g ?` へ移設**: 移設キーが誰にも発見
  できず、ヘルプの存在意義（発見可能性）と矛盾するため不採用。

## Consequences

- 後方検索プロンプトが無くなる。`*`（選択を検索）+ `N` で代替できる。
- キーバインドヘルプは静的テーブル（`minae/src/help.rs`）。バインディング
  変更時はそちらも同期する必要がある（ヘルプ冒頭のコメントに明記）。
- 導入コストが低く、キー再割当だけで巻き戻せるため ADR としては軽量。
