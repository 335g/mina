# Open rejects non-regular and oversized files

mina refuses to open paths that are not regular files (directories, devices such as /dev/zero, FIFOs) and files larger than 16 MiB, reporting "file too large" / "cannot open" in the snapshot status without touching editor state. The daemon checks metadata (is_file + size) before reading. Rationale: v1's full-snapshot-per-command IPC and full-text LSP sync (ADR-0006) make multi-hundred-MiB files unusable regardless of the cap, and an unbounded read is an OOM and hang vector — /dev/zero reads forever, a FIFO blocks forever, a growing log balloons memory. The cap is a plain constant, revisited when diffed snapshots (a v1 non-goal) land and large-file mode becomes viable. Command lines are similarly bounded (1 MiB) so a newline-less stream cannot grow the daemon's read buffer without limit.
